== 目的

KBMemo を構成する3つのアプリケーションを、GitHub Organization 配下の公開
repository として安全に公開するための判断基準と作業順序を定義する。

この文書は公開作業の正とする。秘密情報の監査が完了するまでは、GitHub に
public repository を作成しない。

== 公開状態

== 公開ゲート

次の条件をすべて満たすまで public にしない。

. 使用中または過去に使用した token、password、private key をすべて失効または
  rotation している。
. 全 branch、tag、commit history を secret scanner で検査し、結果を保存している。
. 検出された実秘密情報を `git-filter-repo` 等で全 ref から除去している。
. ライセンスと third-party dependency の配布条件を確認している。
. README だけで development 環境を構築できる。
. 内部 DNS 名、private IP、個人の絶対パス、本番 token の取得手順を一般化している。
. GitHub Actions が fork からの pull request でも秘密情報なしで安全に実行できる。
. Public 化直後に GitHub Private Vulnerability Reporting を有効化し、`SECURITY.md` の報告経路を実際に利用できることを確認する。
. GitHub の Private repository で CI、リンク、README 表示を確認している。

== 作業順序

=== Phase 1: 名称確保

. GitHub に `KBMemo` Organization を作成する。
. `kbmemo`、`tsuzura`、`nyoy` を空の Private repository として作成する。
. README、LICENSE、`.gitignore` はGitHub側で自動生成しない。

=== Phase 2: 公開監査

. `gitleaks` を固定バージョンで導入する。
. working tree と全 Git history を検査する。
. 検出結果を、値を含めず repository ごとの監査記録へ残す。
. 実秘密情報が見つかった場合は、先に資格情報を失効してから履歴を書き換える。
. Gitea 上の古い ref と clone から秘密情報が再流入しない運用を決める。

=== Phase 3: 公開向け整備

. 3 repository の LICENSE を統一する。
. README に製品間の関係、依存サービス、最小起動手順を追加する。
. Gitea URLをGitHub URLへ変更する。
. deploy と runbook のホスト固有値を環境変数または例示名へ置き換える。
. `SECURITY.md` と `CONTRIBUTING.md` を追加する。
. repository description、topics、social preview を準備する。

=== Phase 4: GitHub 移行

実行手順は link:github-migration-runbook.adoc[GitHub 移行 Runbook] を正とする。

. 徒然の未 push commit を先にGiteaへ反映する。
. 空のGitHub repositoryへ全 branchとtagをmirrorする。
. 通常の作業remoteを次の構成へ変更する。

[source,text]
----
origin  git@github.com:KBMemo/<repository>.git
gitea   git@gitea.example.com:organization/<old-repository>.git
----

. default branchを`main`に設定する。
. branch protection、Dependabot、Actions permissionsを設定する。
. GitHubを正、Giteaをbackupまたはread-only mirrorとして扱う。

=== Phase 5: 公開

. Private状態で各repositoryの`bin/ci`を実行する。
. READMEの相互リンクとclone手順を確認する。
. 葛籠、如意、徒然の順でpublicにし、最後に統合動作を確認する。
. 最初のrelease tagを作成し、既知の制限をrelease notesへ記載する。

== 次の作業

. 徒然の repository description、topics、homepage を設定する。
. public 化直前に、固定バージョンの gitleaks で全履歴を再監査する。
