= KBMemo GitHub Public Transition Runbook
:toc:
:toclevels: 2

この手順は link:github-publication.adoc[GitHub 公開準備] の Phase 5 を実施するための
runbook である。対象は `KBMemo/tsuzura`、`KBMemo/nyoy`、`KBMemo/kbmemo` の 3 repository
であり、順序は葛籠、如意、徒然とする。visibility を Public に変更する操作は外部公開を
伴うため、この runbook の承認者が実行する。

== 現在の前提

* 3 repository は GitHub 上で Public、default branch は `main` である。葛籠の
  `develop` branch も GitHub に同期済みである。
* GitHub Actions、`SECURITY.md`、`CONTRIBUTING.md`、README、LICENSE は確認済みである。
* `gitleaks 8.30.1` による全履歴再監査は完了している。徒然・如意はリポジトリ内の
  `.gitleaks.toml` で、文書用の既知プレースホルダーだけを限定許可する。
* 全 repository で Private Vulnerability Reporting を有効化済みである。
* 通常 remote は変更しない。`origin` は Gitea、`github` は GitHub のままとし、公開後も
  両方へ push する。

== 1. 切替直前の確認

各 repository で次を実行する。作業ツリーに未コミット変更がある場合は中断する。

[source,bash]
----
git status --short
git fetch origin --prune
git fetch github --prune
git log --oneline github/main..main
bin/ci

# checksum 検証済みの gitleaks 8.30.1 を使用する
gitleaks detect --config .gitleaks.toml --source . --log-opts='--all' --redact
----

葛籠には `.gitleaks.toml` がないため、最後の command から `--config .gitleaks.toml` を
外す。実秘密情報が検出された場合は、visibility を変更せず、credential の rotation と
全 ref からの履歴除去を完了して再監査する。

GitHub 側の状態も確認する。

[source,bash]
----
for repository in KBMemo/tsuzura KBMemo/nyoy KBMemo/kbmemo; do
  gh repo view "$repository" --json nameWithOwner,isPrivate,defaultBranchRef,url
  gh run list --repo "$repository" --branch main --limit 1
done
----

== 2. Public 化

1 repository ずつ切り替え、その都度 <<public-verification,公開直後の確認>>を完了して
から次へ進む。3 repository をまとめて切り替えない。

[source,bash]
----
repository=KBMemo/tsuzura # 次は KBMemo/nyoy、最後に KBMemo/kbmemo
gh repo edit "$repository" --visibility public
gh repo view "$repository" --json nameWithOwner,isPrivate,url
----

`isPrivate` が `false` であることを確認する。visibility 変更日時、実行者、対象 commit を
公開準備文書または release 記録に残す。

== 3. 公開直後の確認 [[public-verification]]

Public 化後、告知より先に Private Vulnerability Reporting を有効にする。GitHub の
Administration 権限が必要で、成功時の HTTP status は `204` である。

[source,bash]
----
gh api --method PUT "repos/$repository/private-vulnerability-reporting"
----

その後、GitHub の repository Settings > Advanced Security で Private Vulnerability
Reporting が有効であること、Security tab の Advisories で `Report a vulnerability` が
表示されることを確認する。これは Public repository のみで利用できる機能である。

続けて、認証していないブラウザーまたは clone で次を確認する。

. README、LICENSE、`SECURITY.md`、`CONTRIBUTING.md` が表示される。
. README の製品間リンクが GitHub URL を参照し、404 にならない。
. issue form と pull request template が利用できる。
. 最新 GitHub Actions run が成功している。
. `git clone https://github.com/$repository.git` が認証なしで完了する。

== 4. 公開後の運用

* Gitea を同期 backup として残す。push は公開前と同様に `origin` と `github` の両方へ行う。
* 最初の release tag は、既知の制限と互換性を release note に記載してから作成する。
* GitHub の通知設定で Security alerts を受信できることを確認する。Private Vulnerability
  Reporting の通知は repository administrator / security manager の通知設定に従う。

== ロールバック

Public 化直後に問題を見つけた場合だけ、影響を確認した上で Private へ戻す。

[source,bash]
----
gh repo edit "$repository" --visibility private
----

実秘密情報が含まれた場合、visibility を戻すだけでは不十分である。直ちに credential を
失効し、全 ref から除去して再監査する。Gitea backup にも同じ履歴があるため、必要に応じて
同時に対処する。
