= 本番デプロイ手順（Ubuntu 24.04 + nginx）

KBMemo サイトを本番サーバーへデプロイする手順です。

== 前提条件（本番環境）

[cols="2,3",options="header"]
|===
|項目 |値

|OS |**Ubuntu 24.04** LTS（amd64）

|Web サーバー |**nginx**（バーチャルホストでリバースプロキシ）

|アプリ配置先 |**`/home/kensei/sites/kbmemo`**

|公開 URL |**https://kbmemo.org**（`www.kbmemo.org` も許可する想定）

|アプリ実行ユーザー |`kensei`（配置パスと一致）

|DNS |`kbmemo.org`（必要なら `www`）の A/AAAA を本サーバー IP に向ける
|===

* デプロイ方式は **ネイティブ（systemd + Puma/Thruster）** です。nginx が TLS 終端とプロキシを担当し、Rails は **localhost のみ** で待ち受けます。
* リポジトリには Kamal / Docker 用のファイルもありますが、本手順では使用しません。

* 暗号化鍵（BYOK）の詳細: link:../../README.adoc#_active_record_encryption_openai_api_キー_byok[README.adoc — Active Record Encryption]

== 構成概要

[source,text]
----
[ブラウザ] --HTTPS:443--> [nginx @ kbmemo.org]
                              |
                              | proxy_pass http://127.0.0.1:3000
                              v
                    [/home/kensei/sites/kbmemo]
                    Thruster + Puma (PORT=3000, SOLID_QUEUE_IN_PUMA)
                    SQLite x4 → storage/production*.sqlite3
                    memo_git_worktree/  (storage 配下)
                              |
                              v (任意・推奨)
                    [Kroki @ 127.0.0.1:8001]  ← KROKI_URL
----

* **認証**: Rodauth（アカウント作成・メール確認・パスワードリセット）
* **メモ本文**: DB の AsciiDoc が正。Git 作業ツリーは `MemoRepository`（既定 `storage/memo_git_worktree`）
* **図（Mermaid 等）**: Kroki 未起動時は図の保存・レンダリングでエラー

== 本番設定

=== 1. Rails 本番オプション（`config/environments/production.rb`）

nginx 経由の HTTPS では、次を有効にし、ホスト名を合わせます。

[source,ruby]
----
config.assume_ssl = true
config.force_ssl = true

config.action_mailer.default_url_options = { host: "kbmemo.org", protocol: "https" }

config.hosts = [
  "kbmemo.org",
  "www.kbmemo.org"
]
----

Rodauth のメール内リンクもこのホストに依存します。SMTP は別途 `action_mailer.smtp_settings` を設定してください。

=== 2. 環境変数ファイル

**Git にコミットしない** `/home/kensei/sites/kbmemo/.env.production` を作成します（権限 `600`）。

[source,bash]
----
cat > /home/kensei/sites/kbmemo/.env.production <<'EOF'
RAILS_ENV=production
PORT=3000

RAILS_MASTER_KEY=<config/master.key の内容>

MECAB_PATH=/usr/lib/x86_64-linux-gnu/libmecab.so.2
SOLID_QUEUE_IN_PUMA=true

# 図機能（Kroki を同一サーバーで動かす場合）
KROKI_URL=http://127.0.0.1:8001

# OpenAI API キー BYOK を使う場合（bin/rails db:encryption:init の出力）
# ACTIVE_RECORD_ENCRYPTION_PRIMARY_KEY=...
# ACTIVE_RECORD_ENCRYPTION_DETERMINISTIC_KEY=...
# ACTIVE_RECORD_ENCRYPTION_KEY_DERIVATION_SALT=...
EOF
chmod 600 /home/kensei/sites/kbmemo/.env.production
----

[cols="2,3",options="header"]
|===
|変数 |説明

|`RAILS_MASTER_KEY` |必須。`config/credentials.yml.enc` の復号
|`MECAB_PATH` |必須（Ubuntu amd64 の例）
|`KROKI_URL` |図を使う場合
|`MEMO_GIT_WORK_TREE` |省略可。既定は `storage/memo_git_worktree`（アプリ直下）
|===

`config/master.key` はサーバーに置くか、`.env.production` のみに書き **リポジトリには含めない** でください。

=== 3. アプリのビルドと DB

[source,bash]
----
cd /home/kensei/sites/kbmemo
export $(grep -v '^#' .env.production | xargs)

bundle config set --local deployment 'true'
bundle config set --local without 'development test'
bundle install

npm ci
bundle exec rails assets:precompile

bundle exec rails db:prepare
# 必要なら: bundle exec rails db:seed
----

== systemd（アプリ常駐）

`/etc/systemd/system/kbmemo.service` の例です。Ruby のパスは環境に合わせてください（`which ruby` / rbenv）。

[source,ini]
----
[Unit]
Description=KBMemo (kbmemo.org)
After=network.target

[Service]
Type=simple
User=kensei
Group=kensei
WorkingDirectory=/home/kensei/sites/kbmemo

EnvironmentFile=/home/kensei/sites/kbmemo/.env.production

# rbenv 利用時は PATH を通す（例）
Environment=PATH=/home/kensei/.rbenv/shims:/home/kensei/.rbenv/bin:/usr/local/bin:/usr/bin:/bin

ExecStart=/bin/bash -lc 'cd /home/kensei/sites/kbmemo && bundle exec thrust ./bin/rails server'
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
----

[source,bash]
----
sudo systemctl daemon-reload
sudo systemctl enable --now kbmemo
sudo systemctl status kbmemo
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3000/up
----

`/up` が `200` であることを確認してから nginx を設定します。

== nginx バーチャルホスト

=== サイト設定

`/etc/nginx/sites-available/kbmemo.org` の例です。

[source,nginx]
----
# HTTP → HTTPS
server {
    listen 80;
    listen [::]:80;
    server_name kbmemo.org www.kbmemo.org;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name kbmemo.org www.kbmemo.org;

    # certbot 実行後にパスが入る（後述）
    ssl_certificate     /etc/letsencrypt/live/kbmemo.org/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/kbmemo.org/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;

    access_log /var/log/nginx/kbmemo.org.access.log;
    error_log  /var/log/nginx/kbmemo.org.error.log;

    client_max_body_size 50M;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300;
    }
}
----

[source,bash]
----
sudo ln -sf /etc/nginx/sites-available/kbmemo.org /etc/nginx/sites-enabled/
sudo nginx -t
----

=== Let's Encrypt（初回）

SSL 証明書がまだない場合は、一時的に HTTP のみの server ブロックで `certbot` するか、`certbot --nginx` を使います。

[source,bash]
----
sudo certbot --nginx -d kbmemo.org -d www.kbmemo.org
sudo systemctl reload nginx
----

=== 有効化

[source,bash]
----
sudo nginx -t && sudo systemctl reload nginx
curl -fsS https://kbmemo.org/up
----

== Kroki（図機能・任意）

同一サーバーで Docker Compose を使う例です。

[source,bash]
----
cd /home/kensei/sites/kbmemo
docker compose -f docker-compose.kroki.yml up -d
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:8001/health
----

`.env.production` の `KROKI_URL=http://127.0.0.1:8001` と一致させ、`systemctl restart kbmemo` します。

== バックアップ

次を定期バックアップ対象にします（パスはすべて `/home/kensei/sites/kbmemo` 配下）。

* `storage/production*.sqlite3`
* `storage/memo_git_worktree/`
* Active Storage のファイル
* `.env.production` と `config/master.key`（安全な場所へ）

SQLite は可能ならメンテナンス時間にコピーするか、ファイルシステムスナップショットを使用してください。

== トラブルシューティング

[cols="2,3",options="header"]
|===
|症状 |対処

|502 Bad Gateway |`systemctl status kbmemo`、`curl http://127.0.0.1:3000/up`、`.env.production` の `PORT`
|Blocked host |`production.rb` の `config.hosts` に `kbmemo.org` があるか
|リダイレクトループ |`assume_ssl` / `force_ssl` と nginx の `X-Forwarded-Proto` ヘッダ
|JS/CSS なし |`npm ci` と `assets:precompile` を本番で再実行
|`MECAB_PATH` エラー |`.env.production` に amd64 の libmecab パス
|図だけ失敗 |Kroki 起動と `KROKI_URL`
|BYOK 500 |暗号化 3 変数が未設定
|===

== 付録: Kamal / Docker について

`config/deploy.yml` と `Dockerfile` はコンテナデプロイ用です。
本番が **Ubuntu + nginx + `/home/kensei/sites/kbmemo`** の場合は本書の手順を優先し、Kamal の `proxy` / Let's Encrypt は使いません。
