= 本番デプロイ手順（Ubuntu 24.04 + nginx）

KBMemo サイトを本番サーバー（**https://kbmemo.net**）へデプロイする手順です。

== 前提条件（本番環境）

[cols="2,3",options="header"]
|===
|項目 |値

|OS |**Ubuntu 24.04** LTS（amd64）

|Web サーバー |**nginx**（バーチャルホストでリバースプロキシ）

|アプリ配置先 |**`/home/kensei/sites/kbmemo`**

|公開 URL |**https://kbmemo.net**（`www.kbmemo.net` も許可する想定）

|アプリ実行ユーザー |`kensei`（配置パスと一致）

|データベース |**PostgreSQL**（開発: `bowmore:5432`、本番 deploy: `localhost`）。接続情報は **Rails credentials**（`db.*`）

|DNS |`kbmemo.net`（必要なら `www`）の A/AAAA を本サーバー IP に向ける
|===

* デプロイ方式は **ネイティブ（systemd + Puma/Thruster）** です。nginx が TLS 終端とプロキシを担当し、Rails は **localhost のみ** で待ち受けます。
* ログは **`log/production.log` ではなく STDOUT** に出し、systemd の **journal** に記録されます（後述）。
* リポジトリの Kamal / Docker 用ファイルは本手順では使用しません。

* 暗号化鍵（BYOK）: link:../../README.adoc#_active_record_encryption_openai_api_キー_byok[README.adoc — Active Record Encryption]
* メモディレクトリ設計: link:../architecture/memo-directory-layout.adoc[memo-directory-layout.adoc]

== 構成概要

[source,text]
----
[ブラウザ] --HTTPS:443--> [nginx @ kbmemo.net]
                              |
                              | proxy_pass http://kbmemo (upstream → localhost:3007)
                              |   /cable … WebSocket (Action Cable / Turbo Streams)
                              v
                    [/home/kensei/sites/kbmemo]
                    Thruster + Puma (PORT=3007, SOLID_QUEUE_IN_PUMA)
                    PostgreSQL x4 → kbmemo_production*
                    memo_git_worktree/  (storage 配下)
                              |
                              v (任意・推奨)
                    [Kroki @ 127.0.0.1:8001]  ← KROKI_URL
----

* **認証**: Rodauth（Web からの登録はメール確認あり）
* **メモ本文**: DB の AsciiDoc が正。Git 作業ツリーは `MemoRepository`
* **図（Mermaid 等）**: Kroki 未起動時は図の保存・レンダリングでエラー

=== データベース（PostgreSQL）

詳細（開発セットアップ・credentials 構造・Rodauth 連携）は link:../architecture/database.adoc[database.adoc] を参照。

* **PostgreSQL** を使用する（`memos.properties` 等の JSON を正しく扱うため）。
* **開発** は別ホスト（例: `bowmore:5432`）。**本番 deploy サーバー** からは `localhost` で接続する想定。
* 本番は **primary / cache / queue / cable** の 4 データベース（`config/database.yml` の `production:` 参照）。
* **接続情報（ホスト・ユーザー・パスワード・DB 名）は Rails credentials** に書く。`bin/rails credentials:edit` で `config/credentials/db.example.yml` と同じ構造の `db:` セクションを追加する。復号には `RAILS_MASTER_KEY`（または `config/master.key`）が必要。

[source,bash]
----
# 開発マシン — credentials に db.development / db.test を設定
bin/rails credentials:edit

# 本番サーバー — 同じ credentials.yml.enc を使う場合は master.key を .env.production の RAILS_MASTER_KEY に設定
# 本番用に db.production だけ差し替える場合も credentials:edit で db.production を localhost 向けに書く
----

[source,bash]
----
# 本番サーバー（初回）— ロールと DB 作成例（postgres ユーザーで実行）
sudo -u postgres createuser -P kbmemo
sudo -u postgres createdb -O kbmemo kbmemo_production
sudo -u postgres createdb -O kbmemo kbmemo_production_cache
sudo -u postgres createdb -O kbmemo kbmemo_production_queue
sudo -u postgres createdb -O kbmemo kbmemo_production_cable
----

`bin/deploy` / `db:prepare` でマイグレーションが適用される。

==== 旧 SQLite からの移行

既存の `storage/production*.sqlite3` または `storage/development.sqlite3` がある場合、link:../architecture/database.adoc#_旧_sqlite_からのデータ移行[database.adoc — 旧 SQLite からのデータ移行] も参照。

[source,bash]
----
# PostgreSQL にスキーマを用意したあと（db:prepare）
bin/rails kbmemo:db:import_sqlite
# 本番 SQLite を指定する例
SOURCE=/home/kensei/sites/kbmemo/storage/production.sqlite3 bin/rails kbmemo:db:import_sqlite
----

* **primary DB のみ** 対象（Solid Cache / Queue / Cable の SQLite は通常空に近いため未対応）。
* 既定で PostgreSQL 側の既存データは **削除してから** インポートする（`CLEAR=0` で追記モード）。
* 開発用 Gem `sqlite3` が必要（`require: false` — import 実行時のみ読み込む）。
* 本番で import する場合は deploy 後に `bundle install` を再実行すること（`sqlite3` は production bundle に含まれる）。
* アカウント・メモ・ディレクトリを移行した場合は、後述の「初回データ投入」の bootstrap / CLI 管理者作成は **スキップ可能**（既存データを使う）。

移行後の確認:

[source,bash]
----
bundle exec rails runner "puts({ accounts: Account.count, memos: Memo.count }.inspect)"
----

== 本番設定

=== 1. `config/environments/production.rb`

nginx 経由の HTTPS では、次を有効にし、ホスト名を合わせます。

[source,ruby]
----
config.assume_ssl = true
config.force_ssl = true

config.action_mailer.default_url_options = { host: "kbmemo.net", protocol: "https" }

  "kbmemo.net",
  "www.kbmemo.net"
]
----

SMTP は別途 `action_mailer.smtp_settings` を設定してください。

=== 2. `RAILS_MASTER_KEY`（credentials 復号鍵）

**本番専用に新規生成するものではありません。** リポジトリの `config/credentials.yml.enc` と **ペアになる鍵** を本番へ渡します。

[cols="2,3",options="header"]
|===
|やり方 |説明

|開発マシンからコピー |`config/master.key` の内容を `.env.production` の `RAILS_MASTER_KEY` に設定（いちばん多い）
|初回のみ credentials 作成 |`bin/rails credentials:edit` で `master.key` と `credentials.yml.enc` がペアで生成される
|===

[source,bash]
----
# 鍵の確認（開発マシン）。Git にコミットしないこと
cat config/master.key

# 本番 .env.production に同じ値を書く
# RAILS_MASTER_KEY=<64文字の hex>
----

鍵を失うと `credentials.yml.enc` は復号できません。バックアップを別途保管してください。

OpenAI API キー BYOK 用の **Active Record Encryption 3 変数** は別物です（`bin/rails db:encryption:init`）。必要なら `.env.production` と README を参照。

== 初回データ投入（メモディレクトリ + 管理者）

[[memo-directory-bootstrap]]
=== メモディレクトリの初期化（必須）

`MemoDirectory.root`（`full_path: ""`）と `home` / `share` / `public`、各 `u-{account_id}` が無いと、アカウント作成や seed が失敗します。初回は次の **rails runner** で投入してください（`full_path` を明示して NOT NULL を満たします）。

[source,bash]
----
cd /home/kensei/sites/kbmemo
set -a && source .env.production && set +a

bundle exec rails runner "
  now = Time.current

  unless MemoDirectory.where(full_path: '').exists?
    MemoDirectory.insert_all([
      { path_segment: '', label: 'ルート', full_path: '', parent_id: nil,
        created_at: now, updated_at: now }
    ])
  end

  root = MemoDirectory.find_by!(full_path: '')
  labels = { 'home' => 'Home', 'share' => 'Share', 'public' => 'Public' }

  %w[home share public].each do |seg|
    next if MemoDirectory.exists?(full_path: seg)
    MemoDirectory.insert_all([
      { path_segment: seg, label: labels[seg], full_path: seg, parent_id: root.id,
        created_at: now, updated_at: now }
    ])
  end

  Account.find_each do |account|
    %w[home share public].each do |bucket|
      parent = MemoDirectory.find_by!(full_path: bucket)
      seg = \"u-#{account.id}\"
      fp = \"#{bucket}/#{seg}\"
      next if MemoDirectory.exists?(full_path: fp)

      d = MemoDirectory.new(
        parent: parent,
        path_segment: seg,
        label: account.display_name.to_s.truncate(80)
      )
      d.full_path = fp
      d.save(validate: false)
    end
  end

  puts 'memo_directories bootstrap done'
"
----

確認:

[source,bash]
----
bundle exec rails runner "p MemoDirectory.root; p MemoDirectory.pluck(:full_path)"
----

== nginx バーチャルホスト

Turbo Streams（Action Cable）は **`wss://kbmemo.net/cable`** へ WebSocket 接続します。nginx で `Upgrade` / `Connection` をプロキシしないと接続に失敗します。

=== WebSocket 用 `map`（1 回だけ）

`/etc/nginx/nginx.conf` の `http { }` 内、`include /etc/nginx/sites-enabled/*;` の **前** に追加します。

[source,nginx]
----
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}
----

=== サイト設定

`/etc/nginx/sites-available/kbmemo.net`:

[source,nginx]
----
upstream kbmemo {
    server localhost:3007;
}

server {
    listen 80;
    listen [::]:80;
    server_name kbmemo.net www.kbmemo.net;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name kbmemo.net www.kbmemo.net;

    ssl_certificate     /etc/letsencrypt/live/kbmemo.net/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/kbmemo.net/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;

    access_log /var/log/nginx/kbmemo.net.access.log;
    error_log  /var/log/nginx/kbmemo.net.error.log;

    client_max_body_size 50M;

    # Action Cable (Turbo Streams) — WebSocket
    location /cable {
        proxy_pass http://kbmemo;
        proxy_http_version 1.1;
        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        $connection_upgrade;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_buffering off;
        proxy_read_timeout 86400;
        proxy_send_timeout 86400;
    }

    location / {
        proxy_pass http://kbmemo;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 300;
    }
}
----

[source,bash]
----
sudo ln -sf /etc/nginx/sites-available/kbmemo.net /etc/nginx/sites-enabled/
sudo nginx -t
sudo certbot --nginx -d kbmemo.net -d www.kbmemo.net
sudo systemctl reload nginx
curl -fsS https://kbmemo.net/up
----

=== Tsuzura（media.kbmemo.net）

link:../architecture/media-platform.adoc[media-platform.adoc] **Phase 1・2 完了**。写真 API + 最小 Web UI（`kbmemo-media`）を **https://media.kbmemo.net** で公開。ピッカー・運用: link:../architecture/tsuzura-phase2.adoc[tsuzura-phase2.adoc]。

* **upstream 例:** `localhost:3008`（Thruster + Puma、`PORT=3008`）
* **TLS:** `certbot --nginx -d media.kbmemo.net`
* **Rodauth 共有:** KBMemo と同一 PostgreSQL `accounts`、同一 `_kbmemo_session` Cookie（本番は `domain: .kbmemo.net` を両アプリで揃える）
* **ヘルス:** `curl -fsS https://media.kbmemo.net/up`

==== Tsuzura nginx（一括 upload） [[tsuzura-nginx]]

`bin/tsuzura import` は **1 リクエストに全画像** を載せる。`client_max_body_size` が小さいと **413 Request Entity Too Large**。処理時間に合わせ **proxy_read_timeout 600s** 程度を推奨。

[source,nginx]
----
upstream tsuzura {
    server localhost:3008;
}

server {
    listen 80;
    listen [::]:80;
    server_name media.kbmemo.net;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name media.kbmemo.net;

    ssl_certificate     /etc/letsencrypt/live/media.kbmemo.net/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/media.kbmemo.net/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;

    access_log /var/log/nginx/media.kbmemo.net.access.log;
    error_log  /var/log/nginx/media.kbmemo.net.error.log;

    client_max_body_size 512M;
    client_body_timeout 600s;

    location / {
        client_max_body_size 512M;
        proxy_pass http://tsuzura;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_connect_timeout 60s;
        proxy_send_timeout    600s;
        proxy_read_timeout    600s;
    }
}
----

`/etc/nginx/sites-available/media.kbmemo.net`（または `tsuzura`）に配置。

[source,bash]
----
sudo ln -sf /etc/nginx/sites-available/media.kbmemo.net /etc/nginx/sites-enabled/
sudo nginx -t
sudo certbot --nginx -d media.kbmemo.net
sudo systemctl reload nginx
curl -fsS https://media.kbmemo.net/up
----

KBMemo 側の環境変数（`.env.production` 例）:

[source,bash]
----
TSUZURA_BASE_URL=https://media.kbmemo.net
TSUZURA_PUBLIC_URL=https://media.kbmemo.net
KBMEMO_TSUZURA_INTERNAL_SECRET=…  # credentials tsuzura.internal_secret と同一
----

* **Mixed Content:** KBMemo ページは `TSUZURA_PUBLIC_URL=https://media.kbmemo.net` 必須（`http://localhost:3008` の署名 URL を本文に保存しない）。変更後は `systemctl --user restart kbmemo`。
* **メモ編集ピッカー:** ログイン済みで `POST /internal/tsuzura/sign_urls` が **200** であること（422 の多くは CSRF — ページ再読込で meta 同期）。

kbmemo-media 側（`.env.production` 例）:

[source,bash]
----
KBMEMO_TSUZURA_INTERNAL_SECRET=…  # KBMemo と同一
KBMEMO_LOGIN_URL=https://kbmemo.net/login
KBMEMO_HOME_URL=https://kbmemo.net
TSUZURA_CORS_ORIGINS=https://kbmemo.net,https://www.kbmemo.net
----

未ログインで `media.kbmemo.net` を開くと `KBMEMO_LOGIN_URL` へリダイレクト。変更後は `systemctl --user restart kbmemo-media`。

[[logging-journal]]
== ログの参照（journal）

本番の `config/environments/production.rb` は **STDOUT にログ出力** する設定です（Rails 8 のコンテナ向け既定）。

[source,ruby]
----
config.logger = ActiveSupport::TaggedLogging.logger(STDOUT)
----

そのため **`log/production.log` は通常作成されません。** systemd が標準出力を journal に取り込みます。

=== アプリログ（Rails / Puma / Thruster）

[cols="2,3",options="header"]
|===
|目的 |コマンド

|リアルタイム追跡 |`journalctl --user -u kbmemo -f`
|直近 N 行 |`journalctl --user -u kbmemo -n 200 --no-pager`
|今日分 |`journalctl --user -u kbmemo --since today`
|エラー優先 |`journalctl --user -u kbmemo -p err..alert`
|起動直後の失敗 |`journalctl --user -u kbmemo -b -n 100`
|===

`kbmemo` は systemd ユニット名です。`StandardOutput=journal` / `StandardError=journal` をユニットに書いておくと明示的です（上記例に含む）。

=== nginx ログ

* アクセス: `/var/log/nginx/kbmemo.net.access.log`
* エラー: `/var/log/nginx/kbmemo.net.error.log`

[source,bash]
----
sudo tail -f /var/log/nginx/kbmemo.net.error.log
----

=== `log/production.log` をファイルで残したい場合

`production.rb` で File ロガーに切り替え、`log/production.log` の権限と logrotate を別途用意します。単一 VPS + systemd では **journal のまま** を推奨します。

== 更新デプロイ（2 回目以降）

リポジトリ同梱の `bin/deploy` で pull・依存関係・マイグレーション・アセットビルド・再起動を一括実行できます。

`bin/deploy` のヘルスチェックは既定で **https://kbmemo.net/up**（nginx 経由）を叩きます。`config.hosts` に `127.0.0.1` が無いため、`http://127.0.0.1:3007/up` を直接叩くと Host Authorization で拒否されます。アプリだけ確認する場合は `KBMEMO_HEALTH_URL=http://127.0.0.1:3007/up` とし、`bin/deploy` が `Host: kbmemo.net` ヘッダーを付与します。

[source,bash]
----
cd /home/kensei/sites/kbmemo
bin/deploy
----

`main` など特定ブランチを明示する場合:

[source,bash]
----
bin/deploy --branch main
----

`systemctl` だけ手動にしたい場合（`--skip-restart`）:

[source,bash]
----
bin/deploy --skip-restart
systemctl --user restart kbmemo
----

手動で同等の作業を行う場合:

[source,bash]
----
cd /home/kensei/sites/kbmemo
git pull

set -a && source .env.production && set +a
bundle install
npm ci
bundle exec rails db:migrate
bundle exec rails assets:precompile

chmod 750 start.sh   # 必要なら
systemctl --user restart kbmemo
curl -fsS https://kbmemo.net/up
----

新規アカウント追加後に `home/u-{id}` が無い場合は、<<memo-directory-bootstrap>> の runner の `Account.find_each` 部分だけ再実行してください。

== トラブルシューティング

[cols="2,3",options="header"]
|===
|症状 |対処

|`log/production.log` が無い |正常。<<logging-journal>> を参照
|502 Bad Gateway |`systemctl --user status kbmemo`、`journalctl --user -u kbmemo -n 50`、`curl http://127.0.0.1:3007/up`
|WebSocket / Turbo が更新されない |nginx に `map $http_upgrade` と `location /cable` があるか、`curl -i -N … https://kbmemo.net/cable` で `101` になるか確認
|Blocked host |`production.rb` の `config.hosts`
|リダイレクトループ |`assume_ssl` / `force_ssl` と nginx の `X-Forwarded-Proto`
|`MemoDirectory.root` NotFound |<<memo-directory-bootstrap>> を実行
|`Full path can't be blank`（ルート作成） |`insert_all` で `full_path: ''` を明示（手順どおり）
|`NOT NULL constraint failed: full_path` |`full_path` を明示してから `save(validate: false)`
|`Parent Home / Share / Public の直下には移せません` |`u-{id}` 作成は runner 手順どおり（`full_path` 明示 + `validate: false`）
|JS/CSS なし |`npm ci` と `assets:precompile`
|`MECAB_PATH` エラー |`.env.production` の libmecab パス
|図だけ失敗 |Kroki と `KROKI_URL`（ポート **8001**）
|BYOK 500 |暗号化 3 変数
|`Could not find a JavaScript runtime`（ExecJS） |STEM 数式表示時。`bundle install` で `mini_racer` が入っているか確認。`bundle exec rails runner "puts ExecJS.runtime.name"` が `MiniRacer` 等を返すこと。古いデプロイで Node だけに依存している場合は Node.js を入れるか、`mini_racer` 入りのコードを pull して再起動
|===
