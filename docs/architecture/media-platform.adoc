= メディアプラットフォーム — 設計方針（Phase 0・未実装）

KBMemo で写真・画像を **大規模に扱い・編集し・共有する** ための全体設計。
**現状は未実装**の Phase 0 ドキュメント。実装は別リポジトリ（`kbmemo-media` 想定）＋ KBMemo 連携で進める。

前提: `AGENTS.md`（メモ本文の正は DB の AsciiDoc）、link:memo-body-editor-roadmap.adoc[memo-body-editor-roadmap.adoc]（Phase 5f 現行 Git アセット）、link:google-calendar-sync.adoc[google-calendar-sync.adoc]（外部サービス連携の先例）、link:google-photos-integration.adoc[google-photos-integration.adoc]（Google フォト取り込みは Media の入力源の一つ）。

== 要約（意思決定）

[cols="1,3"]
|===
|決定 |内容

|アーキテクチャ
|**Media サービス（別アプリ）+ KBMemo（文章・共有 UX）** の二層

|画像バイトの正
|オブジェクトストレージ（S3 / R2 / MinIO 等）+ Media DB。**Git `{slug}.assets/` は大規模写真向けではない**

|共有の主 UX
|**メモ本文ごと見せる**（KBMemo show）。アルバム単体 URL は副次

|外部利用
|Media REST API + トークン（KBMemo はクライアントの一つ）

|KBMemo 単体への全機能組み込み
|**非推奨**（容量・編集・動画生成・外部 API と相性が悪い）
|===

== 背景：現行 KBMemo の画像

[cols="1,3"]
|===
|現状 |限界

|`MemoAssets` + Git `{slug}.assets/`
|メモ添付の小ファイル向け。10MB/ファイル、メモ単位 commit

|本文 `image::filename[]` + `imagesdir`
|メモ内表示は成立。メモ横断ライブラリ・編集版管理なし

|`MemoPolicy` / `visibility`
|メモ単位の共有。画像コレクション単位の UX なし

|Clip API + `ClipImageImporter`
|公開 HTTP 画像の取り込み。Google フォト等の認証付き源は別途
|===

**規模感（要件）:** 画像ストレージはメモ本文に比べ **おおよそ 1000 倍** を想定する。

== プロダクト像

=== Media サービス（`kbmemo-media` 想定）

写真・動画アセットの **保管・整理・加工・配信** を担う。

* 一括アップロード（EXIF 付き）
* アルバム（写真集）
* 編集（トリミング、回転、顔のぼかし等）
* 選択写真からのショート動画生成
* 外部クライアント向け API

=== KBMemo（既存 `kbmemo_site`）

**文章・ストーリー・公開範囲** を担う。

* アルバムに付随する **長文メモ**（旅行記、キャプション、Wiki リンク）
* **メモ URL で本文ごと共有**（公開 / グループ）
* Notebook・カンバン等、既存プロダクトとの統合
* Media 参照マクロの **表示時解決**

=== 共有の二モード

[cols="1,3"]
|===
|モード |用途

|**ストーリー共有（主）**
|KBMemo メモ show URL。AsciiDoc 全文 + 埋め込みアルバム・写真

|**アルバム単体（副）**
|Media `/albums/:id` — 写真集だけ見せる。KBMemo メモへのリンク optional
|===

== KBMemo と Media の境界

[cols="2,2,2"]
|===
|関心 |Media |KBMemo

|バイト列（原本・派生・動画）
|◎ |×

|アルバム構造・並び・EXIF 索引
|◎ |参照のみ

|トリミング・回転・顔ぼかし
|◎ |×

|スライドショー動画生成
|◎ |×

|AsciiDoc 本文・Wiki リンク
|× |◎

|公開範囲（public / group / owner）
|Media 側は **KBMemo 判定に従う派生 URL** を推奨 |◎（正）

|Notebook / カンバン / タグ
|× |◎

|Git 作業ツリー
|× |メモ `.adoc` のみ（画像 Git 化は小物のみ継続）
|===

**原則:** 画像の「倉庫と加工場」は Media。「意味と公開の物語」は KBMemo。

== データモデル（案）

=== Media 側（`kbmemo-media`）

[cols="1,3"]
|===
|エンティティ |概要

|`Album`
|タイトル、説明（短）、cover_media_id、owner_account_id、日付範囲

|`MediaItem`
|kind（image / video）、storage_key、checksum、width/height、EXIF JSON、captured_at

|`AlbumItem`
|album_id、media_item_id、position

|`MediaRendition`
|media_item_id、variant（thumb / web / edited）、storage_key

|`EditStack`
|media_item_id、非破壊編集 JSON（rotate、crop、blur_regions[]）

|`VideoExport`
|入力 media_ids[]、status、output_media_item_id、ffmpeg パラメータ

|`FaceRegion`（任意・Phase 後半）
|検出框、cluster_id、blur 対象フラグ
|===

=== KBMemo 側

**本文（正）** — AsciiDoc に参照を書く:

[source,asciidoc]
----
= 2024 夏 北海道

album::01HALBUM_ID[]

旅行 2 日目。朝食の後、函館山へ。

image::media:01HPHOTO_A[width=720]
image::media:01HPHOTO_B[]
----

**properties（任意）** — 試行錯誤・索引用（link:memo-properties.adoc[memo-properties.adoc]）:

[source,json]
----
{
  "media_album_id": "01HALBUM_ID",
  "media_item_ids": ["01HPHOTO_A", "01HPHOTO_B"]
}
----

**アルバムとメモの関係（案）:**

* 1 アルバム : 0..1 **メインメモ**（KBMemo `Memo`、`properties.media_album_id`）
* または 1 Notebook : 1 アルバム（旅行記ノートブック）

== 機能詳細

=== 一括登録

* API: `POST /v1/media/batch` または presigned URL 連続 PUT
* EXIF `DateTimeOriginal` でソート・アルバム自動提案
* 重複排除: `checksum` 同一なら `MediaItem` を再利用（任意 Phase）

=== 画像編集

[cols="1,2,1"]
|===
|機能 |方式 |Phase

|回転・トリミング
|EditStack + 新 Rendition
|3

|手動ぼかし矩形
|Canvas UI → blur_regions
|3

|顔検出 → 指定以外を blur
|サーバー ML または WASM。除外リスト
|4

|共有前警告
|「未ぼかしの顔が N 件」— 公開 UX
|4
|===

**編集の正:** 非破壊 **EditStack** を推奨（原本 blob は保持、表示は派生 Rendition）。

=== ショート動画

* 入力: 選択 `media_item_ids[]`、表示秒数、トランジション、解像度
* 処理: Media 内 Job + **ffmpeg**（Solid Queue 相当の worker。**KBMemo Puma 内では実行しない**）
* 出力: 新 `MediaItem`（kind: video）または `VideoExport` レコード
* KBMemo 本文: `video::media:01HVIDEO[]` または既存 video マクロ拡張（YouTube 以外の self-host）

=== Google フォト

* 取り込み **先** は Media（バイト + メタ）
* KBMemo 連携は「アルバム取り込み後にメモ作成」
* 詳細: link:google-photos-integration.adoc[google-photos-integration.adoc]（本 doc の入力チャネルとして位置づけ）

== 認証・認可

=== アカウント

[cols="1,3"]
|===
|案 |内容

|**A（推奨検討）** |同一 `accounts.id` を Media DB でも参照。Rodauth セッション or サービス間 JWT

|**B** |Media 独自ユーザー — 同期コスト大。非推奨
|===

=== 画像の閲覧

**推奨:** メモ経由の表示では **KBMemo `MemoPolicy#show?` が通った場合のみ** Media が signed URL を発行。

* Media に独自 public フラグだけ持つと、メモとズレやすい
* アルバム単体 URL は Media 側 `AlbumPolicy`（将来）

=== 外部 API

* KBMemo `clip_api_token` と同型の **Media API トークン**（`account.media_api_token_*` 等）
* スコープ: upload / read / album_manage

== ストレージ・非機能要件

[cols="1,3"]
|===
|項目 |方針

|容量
|メモ比 **~1000 倍**。Git 非使用

|オブジェクトストレージ
|S3 互換 + CDN（Cloudflare R2 等）

|サムネ
|アップロード時非同期生成（thumb / web）

|バックアップ
|DB + bucket ライフサイクル。Git バックアップとは別系統

|既存 Git アセット
|小さい添付・SVG ダイアグラムは **当面 `MemoAssets` 継続**（移行必須ではない）
|===

== KBMemo 連携（表示・編集）

=== 表示パイプライン（案）

[source,text]
----
memo.body（AsciiDoc）
  → MemoAdocIncludes / 既存前処理
  → MediaMacro（新）: album:: / image::media: / video::media:
  → Media API（内部）で URL 解決 + CDN
  → Asciidoctor.convert（safe）
----

=== 編集 UX（案）

* メモ編集: 「Media から選ぶ」「アルバムを埋め込む」→ Media ピッカー（iframe or API）
* アルバム画面（Media UI）: 「KBMemo でメモを書く」→ 新規 Memo + `properties.media_album_id`

== API 概要（たたき・未確定）

Media サービス（`/v1`）:

[cols="1,3"]
|===
|Method / Path |用途

|`POST /v1/media`
|単体アップロード

|`POST /v1/media/batch`
|一括アップロード

|`GET /v1/media/:id`
|メタ + rendition URLs

|`POST /v1/albums`
|アルバム作成

|`GET /v1/albums/:id`
|アルバム + items

|`PATCH /v1/media/:id/edits`
|EditStack 更新 → Rendition 再生成 Job

|`POST /v1/video_exports`
|スライドショー生成 Job

|`GET /v1/video_exports/:id`
|Job 状態・出力 media_id
|===

KBMemo 内部（サーバー間）:

* `POST /internal/media/authorize` — memo_id + media_ids → 短期 signed URL バッチ（要認証）

== フェーズ計画

[cols="1,3"]
|===
|Phase |内容

|**0（本 doc）**
|方針固定。API たたき。リポジトリ分割方針

|**1 — Media MVP**
|upload、Album、list、S3、owner。KBMemo 外から curl 可能

|**2 — KBMemo 連携**

|**4 — プライバシー編集**

|**5 — 動画**
|ffmpeg Job、スライドショー export、KBMemo 埋め込み

|**6 — 外部安定化 + 取り込み**
|API トークン、Google フォト import、監視・クォータ
|===

=== Phase ごとの非ゴール

* **Phase 1:** 編集、動画、KBMemo UI、Google フォト
* **Phase 2:** 顔検出、ffmpeg、Git アセットからの自動移行
* **Phase 3:** ML 顔認識、4K 動画
