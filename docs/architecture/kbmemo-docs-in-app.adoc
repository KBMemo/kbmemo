= KBMemo 内ドキュメント参照設計

開発ドキュメント（リポジトリ `docs/`）やマニュアル・ヘルプを、開発環境および本番の KBMemo 上から **メモとして参照・閲覧** する方針をまとめる。

前提は `AGENTS.md` どおり: **メモ本文の正は DB の AsciiDoc**。Git 作業ツリー（`MemoRepository`）はコミット後のバックアップ層。リポジトリ直下の `docs/` は **アプリ開発用ドキュメント** であり、現状メモシステムとは別系統。

== 背景・目的

* アーキテクチャ doc（本ファイル含む）を KBMemo 上で Wiki リンク・検索・Notebook 目次と組み合わせて読みたい。
* エンドユーザー向け **ヘルプ** や社内向け **マニュアル** も KBMemo で管理し、Notebook（`manual`）で公開したい。
* 開発者向け doc は **Git PR でレビュー可能** な正本を維持しつつ、KBMemo は **閲覧 UI** として使いたい。

== 現状の制約

=== 表示パイプライン

* 画面表示は `memos.body`（DB）を `Asciidoctor.convert` する（`app/helpers/memos_helper.rb` の `memo_html`）。
* `safe: :safe` で変換しており、**文字列入力に base_dir を渡していない**。
* passthrough（`++++` / `pass:[]` / `+++`）は Stored XSS になり得るため、変換前に `MemoAdocPassthroughRestrictor` で無害化する（`docs/architecture/memo-adoc-passthrough-restriction.adoc`）。
* そのため `include::path/to/file.adoc[]` は **リポジトリ `docs/` をそのまま引けない**（ファイルパス解決・サンドボックスの両面で未対応）。

=== Git 作業ツリー

* パス: `config.x.memo_git_work_tree`（既定 `storage/memo_git_worktree`、環境変数 `MEMO_GIT_WORK_TREE` で上書き）。
* メモ 1 件 = DB レコード +（コミット後）`{memo_directory.full_path}/{slug}.adoc` + 任意の `{slug}.assets/`。
* ファイル形式は YAML front matter + AsciiDoc 本文（`MemoRepository#file_contents_for`）。リポジトリ `docs/*.adoc` の素ファイルと **形式が一致しない**。

=== ディレクトリ・権限

* ルート直下バケットは `home` / `share` / `public`（`docs/architecture/memo-directory-layout.adoc`）。
* 一般ユーザーは原則 **自分の `home|share|public` 配下の `u-{id}` 以下** のみ参照（`MemoDirectoryPolicy::Scope`）。
* `admin` は全ディレクトリ参照可。メモ閲覧は引き続き `MemoPolicy`（`visibility`）が正。

== 検討した方式

=== symlink（Git 作業ツリーへ `docs/` をリンク）

== Phase 1: `docs/` 同期 Rake（実装済み）

=== コマンド

[source,bash]
----
bin/rails kbmemo:docs:sync
DRY_RUN=1 bin/rails kbmemo:docs:sync
KBMEMO_DOCS_SYNC_ACCOUNT_ID=1 bin/rails kbmemo:docs:sync
KBMEMO_DOCS_SYNC_COMMIT=1 bin/rails kbmemo:docs:sync   # development のみ Git commit
----

環境変数:

[cols="1,3"]
|===
|変数 |説明

|`DRY_RUN=1`
|DB を更新せず、作成・更新予定のみ表示

|`KBMEMO_DOCS_SYNC_ACCOUNT_ID`
|同期先アカウント（省略時: 最初の admin、なければ id 最小）

|`KBMEMO_DOCS_SYNC_VISIBILITY`
|既定 `owner_read_write`（`group_read` 等も可）

|`KBMEMO_DOCS_SYNC_MEMO_GROUP_ID`
|`group_read` 系のとき必須

|`KBMEMO_DOCS_SYNC_COMMIT=1`
|同期後 `MemoRepository#write_and_commit!`（production ではスキップ）
|===

=== 実装

* Rake: `lib/tasks/kbmemo_docs.rake`（`kbmemo:docs:sync`）
* サービス: `app/services/kbmemo_docs/sync.rb`, `adoc_source.rb`
* ディレクトリ: `MemoDirectory::UserSpace.ensure_subdirectory!` → `share/u-{id}/dev-docs/...`

=== 入力

* ルート: `Rails.root.join("docs")`
* 対象: `**/*.adoc`（必要なら `*.md` は Phase 1 外）

=== 出力（Memo）

[cols="1,3"]
|===
|項目 |ルール

|配置ディレクトリ
|設定可能な `sync_account_id` の `share/u-{id}/dev-docs/...`（パスは `docs/` 以下の相対パスを反映）

|title
|ファイル先頭の `= Title` または front matter の `title`、なければ basename

|slug
|`docs/` 相対パスを `-` 連結して正規化（例: `architecture-notebook-mvp`）。保存時に `-{memo_id}` が付く

|body
|front matter 除去後の AsciiDoc。先頭の `= Title` 行は title 抽出後に除去（表示重複回避）

|visibility
|既定 `owner_read_write`（環境変数で上書き）

|tags
|固定 `docs-sync` + パス由来タグ（例: `architecture`）

|properties
|`{ "docs_sync": { "source_path": "architecture/notebook-mvp.adoc", "content_sha256": "..." } }` — 更新検知・再同期用
|===

=== upsert 方針

* `properties.docs_sync.source_path` で既存メモを特定（なければ新規作成）。
* 本文ハッシュが変わったときだけ `body` / `title` を更新。
* `properties.docs_sync.read_only` を `true` で付与し、KBMemo 上の編集・削除を抑止（Phase 1b）。

=== やらないこと（Phase 1）

* 双方向同期（Memo → `docs/` への書き戻し）
* `include::` の自動展開
* 画像・diagram アセットの自動コピー（本文中パスは後続）

== Phase 1b: 読み取り専用 UI + Notebook 登録（実装済み）

=== 読み取り専用

* `Memo#docs_sync_read_only?` — `properties.docs_sync.read_only` が true のメモ
* `MemoPolicy#update?` / `#destroy?` — read-only では拒否
* show 画面 — 編集・削除ボタン非表示、同期元パスと `kbmemo:docs:sync` の案内を表示
* `MemosController#edit` — read-only 時は show へリダイレクト

=== Notebook 同期

[source,bash]
----
bin/rails kbmemo:docs:sync_notebook
DRY_RUN=1 bin/rails kbmemo:docs:sync_notebook
----

* Rake: `kbmemo:docs:sync_notebook`
* サービス: `app/services/kbmemo_docs/sync_notebook.rb`
* ノートブック: slug 既定 `dev-docs`（`KBMEMO_DOCS_SYNC_NOTEBOOK_SLUG` で上書き）
* `docs_sync` メモを Notebook に登録。`docs/` のディレクトリ深さに応じて `parent_id` ツリーを構成

=== 推奨ワークフロー

[source,bash]
----
bin/rails kbmemo:docs:sync
bin/rails kbmemo:docs:sync_notebook
----

* 1 本目でメモ upsert、2 本目で Developer Docs ノートブックの目次を更新

== Phase 2: システム doc バケット（実装済み）

=== ディレクトリ

[source]
----
system/
  docs/     … 開発・運用ドキュメント（admin 編集、開発者閲覧）
  help/     … エンドユーザー向けヘルプ（admin 編集、public_everyone メモ）
----

* `home` / `share` / `public` / `system` を **ルート直下の保護バケット**として追加（`MemoDirectory::PROTECTED_BUCKET_PATHS`）。
* `MemoDirectory::SystemSpace.ensure_buckets!` で `system` / `system/docs` / `system/help` を冪等作成（migration + seeds）。
* 一般ユーザーの `MemoDirectoryPolicy::Scope` に `system/docs` / `system/help` 以下の **読み取り専用** 参照を追加。

=== 権限

[cols="1,3"]
|===
|操作 |条件

|`system/docs` / `system/help` のディレクトリ編集
|admin のみ（`MemoDirectoryPolicy`）

|`system/*` 配下のメモ編集・削除
|admin のみ（`Memo#system_space_memo?` + `MemoPolicy`）。`docs_sync` read-only は従来どおり全員不可

|閲覧
|`MemoPolicy#show?` — ヘルプは `public_everyone`、開発 doc は `group_read` 等
|===

=== docs 同期先

既定の同期先は **`system/docs/{docs相対パス}`**。

[source,bash]
----
bin/rails kbmemo:docs:sync
KBMEMO_DOCS_SYNC_TARGET=share bin/rails kbmemo:docs:sync   # Phase 1b 互換: share/u-{id}/dev-docs/
----

[cols="1,3"]
|===
|変数 |説明

|`KBMEMO_DOCS_SYNC_TARGET`
|省略時 `system`。`share` で従来の `share/u-{id}/dev-docs/` 配置
|===

== Phase 3: include / 固定 URL / エクスポート（実装済み）

=== include プリプロセッサ

* `MemoAdocIncludes` — `docs_sync` メモ表示時、`properties.docs_sync.source_path` を基準に `Rails.root/docs/` から `include::` を展開（`memo_html` 内、Asciidoctor 変換前）。
* フェンス内の `include::` は展開しない。`docs/` 外へのパス・リモート URL は拒否。

=== 公開ヘルプ `/help`

* `HelpController#show` — slug 既定 `help` の **公開済み manual** Notebook をゲスト閲覧可能な固定 URL で表示。
* ルート: `/help`, `/help/:memo_slug`（`KBMEMO_HELP_NOTEBOOK_SLUG` で slug 上書き）。
* ノートブック show と同一 UI（2 ペイン + ツリー）。ヘッダーに「ヘルプ」リンク（公開 Notebook がある場合）。

=== Notebook エクスポート

[source,bash]
----
NOTEBOOK_ID=1 OUTPUT=tmp/help-export bin/rails kbmemo:notebook:export
NOTEBOOK_SLUG=help OUTPUT=docs/help DRY_RUN=1 bin/rails kbmemo:notebook:export
----

* `Notebooks::Export` — Notebook ツリーを YAML front matter 付き `.adoc` 群として書き出し。
* 子メモは親 slug 名のサブディレクトリに配置。

== Notebook との連携

* **マニュアル / ヘルプ** は Notebook `publication_kind: manual` が向く（2 ペイン + ツリー目次、`docs/architecture/notebook-mvp.adoc`）。
* 同期 Rake で作ったメモを Notebook に登録するタスク（`kbmemo:docs:sync_notebook`）は Phase 1b 候補。
* 公開ヘルプ: Notebook を `publish` + 各メモ `public_everyone`。

== Wiki リンクによる章間参照

`include::` が使えない Phase 0–2 では、**1 ファイル = 1 メモ** とし、章間は Wiki リンクでつなぐ。

[source,asciidoc]
----
詳細は [[notebook-mvp]] を参照。

* <<notebook-mvp#_データモデル,データモデル>> 節
----

* 同期 Rake は slug を `architecture-notebook-mvp-{id}` 形式にするため、Wiki リンクは stem（例: `[[architecture-notebook-mvp]]`）で参照する。
* リポジトリ内の相対リンク（`xref:` 等）は KBMemo 上では機能しないため、同期時に **Wiki リンクへ変換する前処理** は Phase 1 では行わない（手動または将来タスク）。

== 開発環境での使い方

. `bin/rails kbmemo:docs:sync` で `system/docs/` 以下にメモ upsert（従来配置は `KBMEMO_DOCS_SYNC_TARGET=share`）。
. `bin/rails kbmemo:docs:sync_notebook` で Developer Docs ノートブックを更新。
. KBMemo 上でメモ一覧・Wiki リンク・Notebook 目次を確認。
