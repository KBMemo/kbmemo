= テスト健全化ロードマップ（既知の失敗の解決フェーズ）

最近の機能追加（passthrough 制限・メモ管理画面・ディレクトリ picker・コードブロックツールバー等）に伴い、
いくつかのテストが恒常的に失敗、または並列実行で不安定になっている。
本書はそれらを **実測で分類** し、フェーズ単位で解決する計画をまとめる。

== 調査方法

* 失敗テストを `-i` で個別指定し、**単一ワーカー（`PARALLEL_WORKERS=1`）で隔離実行**して再現。
  単体で再現 → 仕様ドリフト／回帰。単体では通る → 並列の状態共有（フレーキー）。
* サンドボックスの `BUNDLE_PATH` で `Bundler::GemNotFound` になるため `env -u BUNDLE_PATH bin/rails test ...` で実行する。

== Phase 1（A・完了）: STEM/latexmath ブロックを passthrough 制限の対象外にする

[NOTE]
====
実装済み。`MemoAdocPassthroughRestrictor#stem_block?`（Ruby）と `isStemBlock`（JS `passthrough_restrict.js`）で、
開始 `++++` 直上の連続メタ行に `[stem]` / `[latexmath]` / `[asciimath]` があるブロックを neutralize 対象外にした。
KaTeX 2 件と restrictor の除外／非除外テストが緑（Ruby 40 runs・JS 8 tests）。
====

=== 原因

`MemoAdocPassthroughRestrictor#restrict_block_passthrough` は `++++` 区切りを **無条件で** literal（`....`）へ置換する。
しかし `[stem]` / `[latexmath]` / `[asciimath]` 属性を持つ `++++` ブロックは passthrough（生 HTML）ではなく
**数式ブロック**であり、Asciidoctor + `asciidoctor-katex` が KaTeX へ変換する対象。これを literal 化すると数式が壊れる。

[source,asciidoc]
----
[stem]
++++
E=mc^2
++++
----

=== 対応

* 開始 `++++` の直前の行が `^\[(stem|latexmath|asciimath)\b` にマッチする場合、そのブロックは neutralize の対象から外す（区切りを残す）。
* インライン `stem:[]` / `latexmath:[]` は元から passthrough 置換の対象外（`pass:[` / `+++` のみ対象）なので変更不要。

=== セキュリティ上の安全性

数式ブロックの出力は KaTeX による MathML/HTML であり、生 HTML の埋め込み経路ではない。
よって除外しても passthrough（`<script>` 等）の Stored XSS 対策は損なわれない。

=== 検証

* `test/helpers/memos_helper_test.rb` の KaTeX 2 件が緑。
* `test/services/memo_adoc_passthrough_restrictor_test.rb` に「`[stem]` ブロックは literal 化しない」「`[pass]`/無属性 `++++` は従来どおり literal 化」を追加。
* JS 側 `packages/adoc-kbmemo/src/passthrough_restrict.js` と `packages/adoc-kbmemo/test/passthrough_restrict.test.js` にも同等の除外を反映（表示・プレビューの整合）。

== Phase 2（B・完了）: UI 仕様ドリフトのテスト追従

実装は正しく、テストの固定アサーションを新 UI へ更新した。

* **dnd バインディング** (`:386`): `assert_includes ..., 'data-controller="memo-directory-dnd"'` を
  `assert_select '[data-controller~="memo-directory-dnd"]'`（語単位一致）へ変更。
* **ディレクトリ表示** (`:886`): 所有者は picker 表示が正のため、picker の隠しフィールド
  `input#memo_show_directory_id_<id>[value=…]` が選択中ディレクトリを反映することを検証。
  非編集ユーザー向けのプレーンリンクは、公開メモを別アカウント（閲覧のみ）で開く
  `show shows directory path link for a viewer who cannot edit` を新設して担保。
* **タグチップ** (`:939`): 所有者ではタグが入力 UI になりチップリンクは出ないため、
  公開メモを閲覧専用ユーザーで開き、`memo_path(?, sidebar_view: "tag", tag_id:)` リンクの
  テキストがタグ名であることを検証する形へ変更。

=== 検証

* 対象テストが単一ワーカーで緑。
* `test/controllers/memos_controller_test.rb` 全体（単一ワーカー）で 81 runs・残る失敗は Phase 3 の
  `draft_saves_all_fields`（slug 派生）1 件のみ。Phase 1/2 起因の退行なし。

== Phase 3（C・完了）: draft の slug 派生挙動を確定

=== 決定

**明示 slug を優先**する現実装を正とした。`Memo#prepare_slug_from_title_and_manual` は
`file_committed_at` があると早期 return し、明示 slug を保持する（一度コミットしたら維持）。
初回コミット前かつ slug 空のときのみタイトルから派生する。

[cols="3,2"]
|===
|条件 |slug

|コミット済み（`file_committed_at` あり）+ 明示 slug |明示 slug を保持（`draft-slug-<id>`）
|初回コミット前 + slug 空 + `title_manual:false` |タイトルから派生（`derived-heading-<id>`）
|===

=== 対応（実施済み）

* `draft saves all fields without validations` の期待値を `draft-slug-#{id}` に修正。
* `draft derives slug from title for an uncommitted memo when slug is blank` を新設し、
  コミット前のタイトル派生を固定。
* 実装変更は不要（現実装が決定どおり）。

=== 検証

* `test/controllers/memos_controller_test.rb` 全体（単一ワーカー）で 82 runs・0 failures。

== Phase 4（D・完了）: 並列テストの Git 作業ツリー隔離

=== 確認できた問題

`config/environments/test.rb` で作業ツリーを boot 時に一度だけ算出していた。

[source,ruby]
----
suffix = [ ENV["TEST_ENV_NUMBER"], Process.pid.to_s ].compact.join("_")
config.x.memo_git_work_tree = Rails.root.join("tmp", "memo_git_test", suffix).to_s
----

* `parallelize(workers:)` は boot **後** に fork するため、`TEST_ENV_NUMBER` は nil、`Process.pid` は親プロセス。
  結果として **全ワーカーが同一ツリーを共有**していた（同時書き込みの競合）。
* さらにワーカー**内**でもツリーがテスト間でロールバックされず、アセット系テストで状態が漏れていた
  （例: `companion diagram svg` が書いた `flow.svg` が `list includes diagram` テストに残り、
  `svg_missing` 判定を崩す）。

=== 対応（実施済み）

* `ActiveSupport::TestCase` に **テストごとの一意な作業ツリー**を設定。
  `setup` で `tmp/memo_git_test/t-<hex>` を作り `config.x.memo_git_work_tree` を差し替え、`teardown` で削除。
  `MemoRepository.new` は呼び出し時に config を読むため差し替えが効く。
* `config/environments/test.rb` の boot 時算出は非並列実行時のフォールバックである旨にコメント修正。
* 併せて発見した別系統の共有 tmp 競合を修正:
  `test/services/kbmemo_asciidoc_samples/seed_test.rb` の teardown が
  共有親ディレクトリを `rm_rf` していたため、一意フィクスチャファイルのみ `rm_f` するよう変更。
  （他の `tmp` 利用テストは `SecureRandom` の一意サブディレクトリで元から安全。）

=== 検証

* 全テストを既定の並列ワーカー数で **4 回連続実行**し、失敗集合が安定（フレーキーなし）。
  `seed_test` / `memo_attachments_test` の間欠失敗は解消。
* 残る決定的失敗は Phase 5 の 2 系統のみ（並列・単一いずれでも再現）。

== Phase 5（追加発見）: フルスイートで表面化した決定的失敗

Phase 4 でフルスイートを並列実行した結果、当初カタログ外の **決定的（単一ワーカーでも再現）** な失敗が判明した。
フレーキーではなく、別タスクとして扱う。

[cols="3,2,3,1"]
|===
|テスト |箇所 |原因 |分類

|`MemoDiagramsControllerTest#edit_*`（2 件）
|`app/views/memo_diagrams/edit.html.slim:16`
|Slim のドット記法に角括弧クラス `bg-[var(--kb-bg-muted)]` を含めており parse エラー（ページ全体が描画不能）。AGENTS.md の Slim ルール違反。
|実バグ

|`MemosControllerDocsSyncTest#sidebar_tab_links_stay_on_show_when_docs_sync_memo_is_not_file-committed`
|`test/controllers/memos_controller_docs_sync_test.rb:33`
|`.kb-sidebar-tab-bar a[href=memo_path(?, sidebar_view: "tag")]` が見つからない。docs_sync メモのサイドバータブ href の仕様ドリフト。
|要確認

|===

=== 対応案

* **Slim parse**（実バグ・低リスク）: `edit.html.slim:16` を `div class="… bg-[var(--kb-bg-muted)] …"` 形式へ書き換える
  （ドット記法をやめる）。表示と editor ページの回復が目的。
* **docs_sync サイドバー**（要確認）: docs_sync メモ表示時のタブ href の現行仕様を確認し、
  実装が正なら Phase 2 と同様にテストを追従、テストが正なら実装を修正。
