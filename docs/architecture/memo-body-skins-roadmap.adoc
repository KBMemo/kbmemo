= メモ本文スキン機構ロードマップ（テーマ機能の改善）

https://github.com/asciidoctor/asciidoctor-browser-extension[asciidoctor-browser-extension] の
Theme/Stylesheet 機能を参考に、KBMemo のテーマ機能を拡張する計画。

== 背景: 拡張機能との設計差

[cols="2,3,3"]
|===
|観点 |asciidoctor-browser-extension |KBMemo 現状

|本文の見た目
|フル CSS スキンを多数から選択（`github` / `riak` / `notebook` / `tufte` など。構造・タイポも変わる）。https://github.com/darshandsoni/asciidoctor-skins[asciidoctor-skins] 由来。
|`--mg-*` トークンで material-grey 1 種を**配色のみ**可変。

|chrome と本文
|本文（記事 HTML）のみ。アプリ chrome は持たない＝独立。
|`--mg-*` の上書きが `data-kb-theme-base` に**連動**（一体）。

|カスタム CSS
|任意 CSS を追加／削除（"Add a stylesheet"）。
|Theme Studio の**トークン編集のみ**（生 CSS 不可）。

|適用切替
|ドロップダウン＋ファイル単位 `?stylesheet=`。
|ヘッダのテーマ select＋Theme Studio。
|===

KBMemo の「配色バリエーション」は既に十分強い。取り込む価値が高いのは
**「本文の見た目を chrome テーマと独立に、フルスタイルシート単位で選べるスキン機構」**。

== 設計方針

=== 新しい独立次元: `data-kb-skin`

`<html>` に 3 つ目の属性 `data-kb-skin="<skinId>"` を追加し、chrome テーマ（`data-kb-theme` /
`data-kb-theme-base`）とは独立に本文スキンを切り替える。

* `auto`（既定）— 本文は従来どおり chrome テーマの `--mg-*` に追従（**既存挙動と完全互換**）。
* builtin フルスキン — `github` / `tufte` / `notebook` / `riak` など。スコープ付き CSS で本文を全面的に上書き。
* `custom-skin-<uuid>` — ユーザー定義 CSS を `<style id="kbmemo-custom-skin-style">` で注入。

=== 適用先（スコープ）

show・編集プレビュー・WYSIWYG の 3 セレクタすべてに効かせる:

[source,css]
----
html[data-kb-skin="github"] .memo-body.asciidoctor,
html[data-kb-skin="github"] .memo-body-editor__preview-content.asciidoctor,
html[data-kb-skin="github"] .memo-body-editor__wysiwyg-content.asciidoctor { ... }
----

=== カスケード戦略（auto とフルスキンの分離）

構造的な漏れを防ぐため、**`themes.css` の本文（`.memo-body` / `--mg-*`）に対する
テーマ別上書きは `auto` のときだけ効く**ように限定する。

* themes.css の本文系上書き（`--mg-*` 再定義・`.memo-body.asciidoctor ...` ブロック）に
  `[data-kb-skin="auto"]` 限定を付ける。
* フルスキン CSS（`memo-skins.css`）は `themes.css` の後に import し、`--mg-*` を含め本文を**全定義**する。
* これにより「auto = テーマ追従」「フルスキン = スキンが本文を全面制御」がカスケード上きれいに分離する。

=== 永続化

既存のテーマ永続化に相乗りする（localStorage + DB + FOUC 防止ブートストラップ）。

* localStorage `kbmemo_themes_v1` に `activeSkinId` / `customSkins[]`（`{ id, name, css }`）を追加。
* `accounts.theme_preference` JSON に `active_skin_id` / `custom_skins` を追加（`AccountThemePreference` を拡張）。
* `/theme.json`（show/update）でスキンも往復。
* レイアウトの anti-FOUC インラインスクリプトで `data-kb-skin` を bundle 前にセット。

=== UI

* ヘッダのユーザーメニューに**スキン選択 select**を追加（テーマ select の隣）。
* Theme Studio に「本文スキン」セクション（builtin 選択＋カスタム CSS 追加/削除）。
* asciidoctor-skins の配色プリセット（`asciidoctor_skin_presets.js`）を拡充。

== 留意点

* 既定 `auto` で**既存ユーザーの見た目は不変**であること（回帰させない）。
* Phase 1 実装メモ: localStorage（`kbmemo_themes_v1`）に `activeSkinId` / `customSkins` を追加済み。
  ログイン時の DB 同期はまだ無いので、別端末間の同期は Phase 3 で対応。anti-FOUC スクリプトは
  account theme シード時に skin フィールドを保持するよう変更済み。
* Phase 2 実装メモ: `memo-skins.css` を「汎用フルスキン層（`html:not([data-kb-skin="auto"]) :is(...)`）＋
  スキン別トークン」構成に整理。各スキンは `--mg-*` / `--skin-*` を差し替えるだけ。
  builtin スキン = `auto` / `github` / `tufte` / `notebook` / `dark` / `riak` / `medium`。
  Web フォント（et-book・Architects Daughter 等）は同梱せず system フォントへフォールバック。
* Phase 3 実装メモ:
  ** `AccountThemePreference` に `active_skin_id` / `custom_skins`（`{id,label,css}`）を追加し、
     `/theme.json`（GET/PATCH）・anti-FOUC ブートストラップ・`theme_sync.js` の往復に skin を載せた。
     これにより `pullThemeFromServer` 等が skin を破棄しなくなり、ログインユーザーの端末間同期が成立。
  ** Theme Studio に `skin-studio` コントローラの「本文スキン」セクション（builtin 選択＋カスタム CSS の
     追加/編集/削除）を追加。skin 変更も `SKIN_CHANGE_EVENT` 経由で DB へ debounce 同期。
* サニタイズ方針（確定）: 本文スキンのカスタム CSS は当該アカウント自身のページにしか描画されず、
  `to_json`（`escape_html_entities_in_json`）でインライン埋め込みも安全。サーバ側 `sanitize_skin_css` で
  外部 `@import` を除去（追跡・外部取得の遮断）し、`CUSTOM_SKIN_CSS_LIMIT`（20,000 文字）で肥大化を制限する。
  CSS 実行能力は無いため JS 実行リスクは無い。スコープは作者の責務（`.memo-body` 配下推奨）とし、
  汎用フルスキン層は `:not([data-kb-skin^="custom-skin-"])` で除外して material-grey 基底に重ねる構成。
* Phase 4 実装メモ:
  ** Theme Studio の「AsciiDoc プリセット」を asciidoctor-skins の `:root` パレット由来で拡充
     （material grey/blue/green/teal/red/purple/orange/brown、dark、clean、tufte、fedora、gazette、
     notebook、ubuntu、italian-pop、monospace の計 17）。`<option>` は `populateAdocPresets()` で
     `ASCIIDOCTOR_SKIN_PRESETS` から動的生成し、追加時に view 修正が不要。
  ** `adocSkinsYamlToVariables` の本文テキスト導出を修正。asciidoctor-skins では `black` が本文色のため、
     `black` があれば `--mg-text` を `black` 由来にし、無い暗パレットのみ `white`(on-primary) へフォールバック。
     これで白背景パレット適用時に本文が白く潰れる不具合を解消。
* Slim のドット記法は `[` を含むクラス名を解釈できないため、角括弧ユーティリティは `class="..."` で書く。
