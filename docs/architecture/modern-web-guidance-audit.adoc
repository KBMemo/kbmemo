= Modern Web Guidance ベースの Web 実装監査メモ
:toc:

このメモは、2026-06-11 時点の `kbmemo_site` を、Chrome の Modern Web Guidance を軸に
HTML / CSS / JavaScript / accessibility / performance / security の観点で見直し、
**実装修正の優先順位**を整理したものです。

== 参照

* Chrome for Developers, "Get started with Modern Web Guidance"
  https://developer.chrome.com/docs/modern-web-guidance/get-started
* Chrome for Developers, "Explore Modern Web Guidance skills"
  https://developer.chrome.com/docs/modern-web-guidance/explore-skills
* MDN, "HTML: A good basis for accessibility"
  https://developer.mozilla.org/en-US/docs/Learn_web_development/Core/Accessibility/HTML

Modern Web Guidance は、semantic HTML、native interactive APIs、focus management、resource prioritization、
XSS/CSP/cookies などを中心に、モダンな Web 実装へ寄せるための指針群として整理されている。
本監査もその分類に合わせる。

== 実施ログ

=== 2026-06-11

* CSP は `config/initializers/content_security_policy.rb` で report-only として有効化。既存ページの違反収集を前提にし、enforcement は次段階に残す。
* `application.html.slim` / `diagram_viewer.html.slim` のテーマ初期化 inline script を削除し、`application` entrypoint が `script[type="application/json"]` の account theme payload を読む構成へ変更。
* `memo_ai_panel_controller.js` の error 表示を `innerHTML` から `textContent` / `createElement` ベースへ変更。
* `application.html.slim` / `diagram_viewer.html.slim` / `svg_editor.html.slim` に `lang="ja"` を付与。
* `application.html.slim` に skip link と `main#main-content` を追加。
* Tsuzura picker dialog に `aria-labelledby` / `aria-describedby` を追加。
* `code_block_tools_controller.js` の sanitize 済み SVG 注入を `replaceWithSanitizedSvg` に隔離し、loading / error 表示を DOM API ベースへ変更。
* `user_menu_controller.js` に `aria-controls`、open 時 focus、Escape focus return、Arrow/Home/End navigation を追加。

== 現状の良い点

* semantic な `button` / `details` / `dialog` をすでに多用している。
* flash 通知に `aria-live="polite"` が入っている。
* avatar と本文画像系には `loading="lazy"` / `decoding="async"` が使われている。
* production では `force_ssl = true`、host 制限、cookie store を使っている。
* Tailwind 依存を外し、テーマ設計を `themes.css` と Open Props に寄せている。

|P0
|Security
|`code_block_tools_controller.js` の SVG 注入は `replaceWithSanitizedSvg` に隔離済み。loading / error 表示は DOM API ベースへ変更済み。
|次は sanitize 契約を endpoint / response header / controller test でより明示する。

|Accessibility / HTML
|`application.html.slim`、`diagram_viewer.html.slim`、`svg_editor.html.slim` は `lang="ja"` 付与済み。
|将来 i18n を広げるなら locale 連動にする。

|P1
|Accessibility / HTML
|`application.html.slim` は skip link と `main#main-content` 追加済み。
|長いナビゲーションを持つ layout が増えた場合は同じ pattern を使う。

|P1
|Accessibility / JS
|`user_menu_controller.js` は `aria-controls`、open 時の初期 focus、Escape の focus return、menuitem の Arrow/Home/End 移動を追加済み。
|select は native 操作を優先して Tab 移動対象に残す。今後 popover 化する場合は role 設計も再評価する。

|P1
|Accessibility / HTML/JS
|Tsuzura picker は `aria-labelledby` / `aria-describedby` 付与済み。ディレクトリ dialog は Ajax で body を差し替えるため未対応。
|ディレクトリ dialog は読み込まれる見出し ID と wrapper の `aria-labelledby` を controller 側で接続する。

|P1
|Accessibility
|サイドバー resizer は `role="separator"` を持つが `tabindex="-1"` で、キーボード操作経路が無い。
|separator を本当に操作可能にするなら **focusable + Arrow key resize** を実装する。やらないなら単なる装飾 divider として扱い、role を外す。

|P1
|Forms / Accessibility
|エラー表示は視覚中心で、`aria-invalid`、`aria-describedby`、field 単位の関連付けが不足している。
|Rails form helper 出力に合わせて、invalid 時は `aria-invalid="true"`、field error message の ID を `aria-describedby` へ接続する。summary がある場合は先頭に置く。

|P1
|Performance / JS
|直近の `bundle exec vite build --force` では `application` が約 1.79 MB、`svg_editor` が約 2.19 MB。さらに ineffective dynamic import 警告が出ている。
|**route 単位の bundle 分離**を進める。特に `@kbmemo/adoc-codemirror` 系は static import と dynamic import が混在しているため、読み込み境界を整理する。メモ本文 editor、SVG editor、diagram viewer、theme studio は入口をさらに分けられる。

|P1
|Performance / HTML/JS
|テーマ初期化 inline script は削除済み。account theme payload は JSON script tag で渡している。
|今後は初期描画前のテーマちらつきと CSP enforcement の両立を検証する。

|P2
|CSS
|`utility-compat.css` が Tailwind 置換レイヤとして成長している。現状は実用上問題ないが、長期では再び utility 膨張に戻りやすい。
|「互換 layer は縮小専用」と決め、**新規 utility 追加を抑制**する。原則は semantic class を `themes.css` に置く。lint かレビュー項目で固定するとよい。

|P2
|HTML / Accessibility
|現在も semantic HTML は比較的良いが、custom popup / picker の増加で native 機能との差が広がりやすい。
|Baseline を明示した上で、可能な箇所は `dialog` / `details` に寄せ、将来的には `popover` も検討する。Modern Web Guidance でも native overlays と focus management が中心テーマになっている。

|P2
|Performance
|継続的な測定点が docs に無い。
|Lighthouse / CWV の運用基準を docs 化し、最低でも LCP / INP / CLS と bundle size を release 前確認項目にする。

== 補足

Modern Web Guidance は、最新機能を無条件に採用すること自体を目的にしていない。
`Baseline` と fallback を前提に、**native で済むものは native に寄せ、JS は必要なところだけに限定する**
という方向が中心にある。`kbmemo_site` では、すでに `dialog` / `details` / semantic button が入っているため、
全面作り直しではなく、**CSP・focus management・bundle 分割**の3本を先に締めるのが最も効果的である。
