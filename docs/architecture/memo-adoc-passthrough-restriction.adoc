= メモ AsciiDoc passthrough 制限

AsciiDoc の passthrough 記法は HTML をそのまま出力するため、`safe: :safe` だけでは Stored XSS（保存型 XSS）の原因になり得る。
KBMemo では **DB 上のソースは変更せず**、メモ表示・ライブプレビュー・WYSIWYG ブロックプレビューの **HTML 変換直前** で passthrough を無害化する。

== 背景

Asciidoctor の passthrough は次のように生 HTML を出力する。

[source,asciidoc]
----
++++
<script>alert(1)</script>
++++

pass:[<script>alert(1)</script>]

+++<del>removed</del>+++
----

`memo_html` は `safe: :safe` で変換するが、これは include や base_dir 等の制限が主目的であり、passthrough 内の `<script>` やイベント属性は除去されない。
メモは本人・グループ・全公開で共有されるため、悪意ある passthrough が閲覧者のブラウザで実行されるリスクがある。

== 方針

* **正（ソース）**: DB の AsciiDoc 文字列はそのまま保存・編集する。エディタのハイライト・編集ユニット分割も従来どおり。
* **表示・プレビュー**: 変換前に passthrough を neutralize し、HTML として解釈されない形にする。

== 無害化ルール

[cols="2,3"]
|===
|記法 |変換

|ブロック `++++` … `++++`
|区切りを literal ブロック `....` に置換。中身は HTML エスケープされて `<pre>` 表示になる。

|未閉じ `++++`
|先頭を `....` にし、末尾に `....` を追加して literal 化する。

|インライン `pass:[…]`
|先頭に `\` を付与（`\pass:[…]`）し、テキストとして表示する。

|インライン `+++…+++`
|開始 `+++` の前に `\` を付与（`\+++…+++`）し、テキストとして表示する。
|===

**対象外:** 単一プラス passthrough（`+…+`）は Asciidoctor が HTML エスケープして出力するため、現状は制限しない。

== 作者・閲覧者への見え方

* **編集時**: ソース上は `++++` / `pass:[]` / `+++` のまま。シンタックスハイライトも従来どおり。
* **表示時**: ブロック passthrough は literal（等幅・エスケープ）になる。インライン passthrough は記法文字列がそのまま段落内テキストとして見える。
* syntax quick reference の `blocks-passthrough` 例（`<p>` 埋め込み）は、show では HTML レンダリングされず pre 表示になる。これは意図したセキュリティ上のトレードオフ。
